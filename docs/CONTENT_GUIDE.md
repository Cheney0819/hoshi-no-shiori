# 星之栞内容规范

本规范用于保持文章分类、标签、文件名和 Frontmatter 一致。

## 正式分类

每篇文章只选择一个主分类：

- `动画随笔`：动画、电影、角色、场景与观后感
- `技术笔记`：开发、工具、项目实践与问题记录
- `生活记录`：摄影、游戏、灵感和普通日常

如果以后确实出现大量新主题，再增加分类；不要为单篇文章创建新分类。

## 标签规范

- 每篇建议使用 2～5 个标签
- 标签应简短、稳定，避免同义词并存
- 技术名称保留官方大小写，例如 `Astro`、`TypeScript`
- 内容类型不必重复分类名称，标签用于补充具体主题
- 同一概念统一写法，例如统一使用 `前端`，不要同时使用 `Web前端`

## 文件名与 Slug

- 文件名使用小写英文和连字符，例如 `first-astro-project.md`
- `slug` 与文件名保持一致
- 已发布文章不要随意修改 `slug`，避免旧链接失效
- 标题可以使用中文，不影响 URL

## 发布流程

创建文章：

```bash
pnpm new-post "文章标题"
```

新文章默认 `draft: true`，完成以下检查后改为 `false`：

1. 标题与描述完整
2. 分类正确
3. 标签数量合适
4. 封面可正常加载且拥有使用权限
5. 正文没有占位文字
6. 手机和桌面预览正常
7. 需要评论时将 `comment` 改为 `true`

## 推荐文章结构

- 写在前面：交代背景和写作目的
- 正文：使用清晰的二级、三级标题
- 小结：总结重点和后续计划

结构可以按内容调整，不要求所有文章完全一致。
